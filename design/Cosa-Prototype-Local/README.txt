CŌSA PROTOTYPE — LOCAL COPY

OPEN THE APP
1. Extract this whole folder from the ZIP.
2. Double-click index.html to open it in Chrome or Edge.
3. Keep index.html and the assets folder together.
No installation or internet connection is needed to try this exported copy.

WHAT IS INCLUDED
index.html           The complete interactive prototype.
assets/              JavaScript, styles, fonts, images and phone frames.
preview-full.html    Opens a larger preview window.
qa-view.html         Alternate embedded design-review view.
source/              Editable React/TypeScript project, including all original
                     HTML entry, preview and runtime-test files.

The app uses one HTML entry page; the different screens are generated by React.
To change the app, start with source/src/Prototype.tsx and source/src/prototype.css.
The source HTML and test fixture require the development server. They are not
standalone copies of the guest app. The top-level index.html is ready to open.

LATEST FEATURES INCLUDED
- Online pre-check-in with local NRIC/passport image preview and hourly arrival windows.
- One luggage locker per traveller; choose size and drop-off day/hour, check
  availability, place luggage, scan to lock, then scan to unlock and collect.
- Unavailable-locker and failed-access demonstration paths.
- Hotel directions, housekeeping, then shower availability.
- English, Japanese, Chinese, Malay, Korean and French options; some text remains English.
- Coffee, other drinks and quick bites, with one basket across menu categories.
- Room access, concierge and checkout demonstration flows.

All bookings, payments, QR actions, lockers, room access and AI responses are
simulated. Identity photos are handled locally, with no real identity verification.

EDITABLE SOURCE
With Node.js and npm installed: open a terminal in source, run npm ci, then
npm run dev. For a production build run npm run build. The source README includes
historical development notes; this file describes the current packaged version.

The top-level export uses relative asset paths and a deferred browser script so
it can open directly from a local folder. Original source/runtime files remain
unchanged in source. Rebuilding source uses its original hosted-app settings.
